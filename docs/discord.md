# Discord連携

Discordの投稿を会話セッションへ渡す条件と、Discordへの書き込みの制約を定める。入力の種類の一覧と会話セッションのライフサイクルは [SPEC.md](./SPEC.md) にある。

## 受付条件

Luna自身の投稿を除き、以下のメッセージ（`messageCreate`）を受け付ける。

- 常設チャンネル内のすべてのメッセージ
- 常設でないチャンネルまたはスレッドで、Luna宛てにメンションされたメッセージ
- 一時セッションが有効なスコープへ届いたすべてのメッセージ
- ボイスチャンネルに紐づいたスコープへ届いたすべてのメッセージ（[voice.md](./voice.md)）
- `allow_dm = true` の環境に届いたすべてのDM

人間、他のBot、Webhook、Discordのシステムメッセージはすべて入力として受け付ける。親チャンネルで一時セッション中であっても、その配下に作成されたスレッドにはセッションが自動継承されない（スレッド側でのメンションが必要）。

Guildチャンネル配下のスレッドおよびフォーラム投稿は、受信時点でDiscord.jsのキャッシュにLuna自身のメンバー情報が存在する場合にのみ常設として扱われる。キャッシュに存在しない場合は未参加とみなし、常設としては扱わない（外部APIへの追加問い合わせは行わない）。

Guildチャンネル、Guildスレッド、DMはそれぞれ独立した会話スコープとして扱われ、スコープごとに固有の会話セッションが割り当てられる。同一スコープ内の参加者は単一のエージェントのセッションを共有する。

## 集約と順序制御

- 最後に受信したメッセージから `debounce_ms` 待機する。
- スコープ内でユーザーが入力中（typing）の場合、入力が止まって `typing_idle_ms` 経過するまで待機する。
- 待機中に受信したメッセージは、Discordの送信時刻順（同値の場合はメッセージID順）に1つのバッチへまとめる。
- すでに実行中の場合はバッチ化せず、受信順に1件ずつ即座に割り込み入力として渡す。

## 初回コンテキスト

新規セッション開始時は、最初のメッセージバッチより直前の過去ログを最大 `initial_history_limit` 件取得し、古い順に `history` 入力として渡す。これ以降の会話履歴はエージェントのセッション側で保持されるため、Discord APIからの再取得は行わない。Gatewayの切断中に受信できなかったメッセージの補完は行わない。

## スラッシュコマンド

起動時にグローバルコマンド `/luna` を登録する。通常のメッセージを受け付けるスコープで利用可能である（未登録チャンネルでは一時セッション中のみ）。応答は実行者にのみ表示されるエフェメラルメッセージとする。

- `/luna model [model] [effort]`: セッションで使用するモデル（`provider/model`）と推論強度を変更する。モデルのカタログにある組み合わせのみ受け付け、現在のセッションに即時適用する（セッション終了時に設定は破棄される）。
- `/luna end`: 現在のセッションの終了を要求する。実行中の処理と記憶保存の完了を待ってセッションを閉じる。
- `/luna channel add` / `/luna channel remove`: 実行したチャンネルを常設チャンネルに追加または削除する。Guild内であれば誰でも実行可能であり、`config.toml` を更新して即座に反映する。

## メッセージの編集・削除とリアクション

会話セッションが知っているメッセージについて、Luna以外による編集・削除と、リアクションの追加・削除をそのセッションへ入力として渡す。セッションが知っているメッセージは次の3つで、セッションを閉じると忘れる。

- そのセッションで受け付けたメッセージ
- 初回コンテキストとして渡した過去ログ
- セッションが開いている間に、そのスコープへ投稿されたLuna自身のメッセージ

これらの入力は通常の投稿と同じく集約と順序制御を経て実行を始め、実行中なら割り込み入力になる。セッションのないスコープへの変更、知らないメッセージへの変更、記憶保存や終了の処理に入ったセッションへの変更は渡さず、新しいセッションも始めない。

| 入力                     | `data`                                                                           | `occurredAt` |
| ------------------------ | -------------------------------------------------------------------------------- | ------------ |
| 編集                     | `{ scope, message }`（編集後のメッセージ全体）                                   | 編集時刻     |
| 削除                     | `{ scope, messageId }`                                                           | 受信時刻     |
| リアクションの追加・削除 | `{ scope, messageId, emoji, user }`（`user` は `{ id, username, displayName }`） | 受信時刻     |

- 編集は編集時刻が変わった更新に限る。埋め込みの展開やピン留めによる更新は渡さない。
- Discordは削除した人を通知しないため、Luna自身の投稿の削除は投稿者で見分けて渡さない。投稿者がキャッシュに残っていないメッセージは見分けられず、Luna自身の投稿でも渡す。
- リアクションの全削除、絵文字ごとの削除、メッセージの一括削除は渡さない。Lunaの起動後に一度も見ていないユーザーによるリアクションの削除は、そのユーザーがDiscord.jsのキャッシュになく受信されないため渡せない。

## Discordへの書き込み

- 送信・返信では、文字数上限やファイルの存在・読み取り可否を事前に検証する。失敗はツールの失敗として返し、自動分割や平文変換は行わない。
- `edit_message`（本文だけを置き換え、添付はそのまま残す）と `delete_message` は、Luna自身の投稿にだけ使える。他人の投稿を指定するとツールの失敗を返す。
- `start_typing` で始めたタイピング表示は、`stop_typing` または実行の完了で止まる。

## 内部設計

- Gatewayは `messageCreate`・`messageUpdate`・`messageDelete`・`messageReactionAdd`・`messageReactionRemove`・`typingStart` を購読する。初回コンテキストの過去ログはキャッシュせずに取得するため、`Partials.Message` と `Partials.Reaction` を有効にし、キャッシュにないメッセージの変更も受け取る。
- `DiscordConversationController` は、Luna自身の投稿を `remember` で、他の人による編集・削除・リアクションを対象メッセージIDつきの `acceptFollowUp` で `ConversationCoordinator` へ渡す。どのメッセージを知っているかの判定はコーディネーターに任せる（[ARCHITECTURE.md](./ARCHITECTURE.md) の会話セッションの状態遷移）。
- Discordツールは読み取り・書き込み・会話委譲を1つのツールプロバイダにまとめ、作業エージェントには読み取りだけのプロバイダを渡す。
- 会話委譲は、イベント実行がDiscord上で対話を始めたい時に、自分で投稿せず対象スコープの会話セッションへイベントを渡して対話を任せる。
